# Terminology audit

Every technical, sophisticated, or jargony word and phrase in the repo's prose,
scored for whether a reader outside this project can understand it — and
cross-checked against the SIL codebases sil-lift is meant to interoperate with.

## Scope

**This repo**: all Python comments and docstrings under `src/`, `tests/`, and
`scripts/`, plus all Markdown outside `.claude/` — `README.md`,
`CHANGELOG.md`, `CONTRIBUTING.md`, `AGENTS.md`, `CLAUDE.md`, `docs/en/**`, and
both `PROVENANCE.md` files. Fenced code blocks are excluded from Markdown
counts (identifiers are not prose); API names such as `Extras` or `--strict`
are counted only where they appear in running text.

**Sibling repos**, searched for every term below:

- `../FieldWorks` (`*.cs`, `*.md`, `*.htm`) — the format's dominant producer.
- `../libpalaso` (`*.cs`, `*.md`) — `SIL.Lift`, `SIL.DictionaryServices`.
- `../lift-python` (`*.md`) — **sil-lift's own design and research repo**, so
  its counts are self-referential. They show where a term entered this
  project, not that anyone else uses it.

Two caveats on reading the ecosystem counts:

- **A zero is only evidence for informal or coined wording.** FieldWorks is a
  C# desktop application, not an XML-schema library, so `mixed content`,
  `content model`, `zip bomb`, `path traversal`, and `clamp` scoring 0 there
  says nothing against them — they are standards terms whose home is the W3C
  and OWASP, cited in the external-usage column.
- **A high count can be a collision, not a precedent.** `slot` scores 442 in
  FieldWorks because it means *inflectional affix slot*. That is a reason to
  stop using the word, not to keep it. The column notes the sense wherever it
  differs from sil-lift's.

## Tiers

- **T1 — Coined here.** No usage in this sense anywhere searched. A reader
  cannot look it up and cannot infer it. Change these.
- **T2 — Borrowed metaphor or informal.** A real word used figuratively, or
  one whose better-known meaning collides with the intended one.
- **T3 — Real technical term, heavy or under-explained.** Correct usage, but
  abbreviated without expansion, or steeper than the audience needs.
- **T4 — Settled vocabulary.** Standards and lexicography terms a LIFT reader
  is expected to know. Keep.

**File column**: filenames are unique across this repo, so paths are shortened
(`_writer.py`, `guides/cli.md`, `corpus/PROVENANCE.md`,
`schemas/PROVENANCE.md`). Lists longer than four files are truncated with a
count of the rest. **Ecosystem column**: occurrence counts as
FieldWorks / libpalaso / lift-python.

## Summary

### The correction

**"Residue" is not a coinage — it is the ecosystem's word, and matching it is
right.** FieldWorks uses it 87 times for exactly sil-lift's meaning:
unmodeled LIFT content is serialized into a `<lift-residue>` blob held in a
`LiftResidue` field, written by `WriteLiftResidue()`, with a user-visible
progress string "Writing accumulated residue"; a FLEx test asserts that
`example.LiftResidue` contains `totallyunknowntrait`. libpalaso's LIFT builder
says it plainly: "we put in the xml residue for round-tripping."

One detail worth matching more closely: **FLEx never says bare "residue" for
this.** Bare "residue" in FieldWorks means `ImportResidue` / the
`import-residue` LIFT field — "residue left over from importing a standard
format file into FieldWorks (or LinguaLinks)" — a user-visible field defined in
the LIFT standard's field list and present in sil-lift's own
`ranges/test20080407.lift` fixture. FLEx has code that moves content *from*
`ImportResidue` *to* `LiftResidue` precisely because they are different things.
So: say **"LIFT residue"** on first use in each file, cite `LiftResidue` once
in `_extras.py` so a FLEx developer can connect the two, and keep `Extras` as
the Python type name.

The corollary: `out-of-schema` scores 0 in both C# repos. It is *this
project's* phrasing, not the ecosystem's — so it belongs alongside "LIFT
residue" as a plain-English gloss, not as a replacement for it.

### What the cross-repo search changed

Ten flagged terms turned out to have real ecosystem precedent and are now
**Keep**: `residue`, `POS` (986 uses in FieldWorks), `sanity` (58),
`spurious` (34), `surface` (60, same API sense), `bail out` (15), `pump`
(11 + 9), `plumbing` (7, same informal sense), `safety net` (6), and
`MDF` (19).

### What it confirmed, more strongly than before

Four terms don't just lack precedent — the ecosystem already uses the word for
something else, in this exact domain:

- **`slot`** means an inflectional affix slot in FLEx (`IMoInflAffixSlot`, 442
  uses). Using it for a byte position in a lexicon library is misleading.
- **`anchor`** means a text-selection endpoint (`SelLimitType.Anchor`, 586 uses
  across the two C# repos) — and sil-lift's readers come from there.
- **`matrix`** appears 24 times in FieldWorks, always as a comparison table.
- **`twin`** names a lexical relation type (`Twin`/`Twain`) in FLEx test data.

And **`canonical`** now has three meanings in one ecosystem: W3C C14N,
