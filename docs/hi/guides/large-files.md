# बड़ी फ़ाइलें (स्ट्रीमिंग)

`load()` पूरे ऑब्जेक्ट ग्राफ़ का निर्माण करता है। सैकड़ों एमबी के शब्दकोशों के लिए, स्ट्रीमिंग एपीआई सीमित मेमोरी में एक समय में एक प्रविष्टि को संसाधित करता है। यह समान `Entry` प्रकार का परिणाम देता है, इसलिए एक मोड के लिए लिखा गया कोड दूसरे मोड में भी काम करता है।

## पढ़ना

```python
import sil_lift

with sil_lift.open_reader("big.lift") as reader:
    header = reader.header         # पहले से पार्स किया गया (एंट्रीज़ से पहले)
    for entry in reader:          # लेज़ी Iterator[Entry]
        ...
```

## लिखना

```python
with sil_lift.open_reader("big.lift") as reader, sil_lift.open_writer(
    "out.lift", header=reader.header, producer="my-script"
) as writer:
    for entry in reader:
        if not entry.date_deleted:    # उदाहरण के लिए, हटाए गए के रूप में चिह्नित प्रविष्टियों को छोड़ें
            writer.write(entry)
```

टिप्पणियाँ:

- लेखक का आउटपुट बिल्कुल वैसा ही है जैसा पूर्ण-दस्तावेज़ कैनोनिकल सीरियलाइज़र उसी सामग्री के लिए उत्पन्न करेगा; दोनों मोड कभी अलग नहीं होते।
- स्ट्रीमिंग मोड किसी भी स्रोत बाइट का पुन: उपयोग नहीं करता: आउटपुट हमेशा मानक होता है। रूट-स्तर का LIFT अवशेष (<lift> पर प्रविष्टियों के बीच और स्कीमा-बाहर के गुणों पर टिप्पणियाँ) हटा दिया जाता है, लेकिन प्रविष्टियाँ और हेडर अपना स्वयं का अवशेष बनाए रखते हैं।
- ../fidelity.md#saving-an-edited-document`Lexicon.save()` के विपरीत, स्ट्रीमिंग मोड कोई टाइमस्टैम्प नहीं उत्पन्न करता। एक प्रविष्टि को उसकी मौजूदा तारीखों के साथ लिखा जाता है: एक स्ट्रीमिंग पास दस्तावेज़ को जैसा था वैसा कभी नहीं देखता, इसलिए यह नहीं बता सकता कि आपने कौन-सी प्रविष्टियाँ बदलीं। जिन पर इस पास ने फिर से लिखा है, उन पर स्वयं `entry.date_modified` सेट करें।
- यदि `open_writer` ब्लॉक के शरीर में raise होता है, तो फ़ाइल स्पष्ट रूप से अधूरी रह जाती है (कोई समापन `</lift>` नहीं होता)। यह आधे-लिखे शब्दकोश को पूरा दिखने से रोकता है।
