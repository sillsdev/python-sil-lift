# कमांड लाइन (सीएलआई)

पैकेज (`pip install sil-lift`) इंस्टॉल करने से `sil-lift` कमांड भी इंस्टॉल हो जाता है।

```
sil-lift validate PATH [--format {text,json}] [--strict] [--no-check-media]
                  [--allow CODE[,CODE...]]... [--require-ids]
    सभी समस्याएँ, फ़ाइल/प्रविष्टि/पंक्ति के साथ; त्रुटियों पर 1 पर निकास

sil-lift stats PATH [--format {text,json}]
    प्रविष्टि/अर्थ/भाषा की गिनती (स्ट्रीमिंग; कोई भी आकार)

sil-lift sort PATH [-o OUT]
    मानक रूप से क्रमबद्ध, diff-तैयार प्रतिलिपि (डिफ़ॉल्ट: उसी स्थान पर)

sil-lift check-media PATH
    अनुपस्थित, गलत वर्तनी वाली और अनाथ मीडिया रिपोर्ट; यदि अनुपस्थित/गलत वर्तनी हो तो 1 पर बाहर निकलें

sil-lift export PATH [-o OUT]  [--langs L] [--tsv]
    प्रत्येक लीफ़ सेंस के लिए एक पंक्ति (सबसेंस समतल) CSV/TSV (स्ट्रीमिंग) में
```

## सत्यापित करें

`validate` प्रत्येक निष्कर्ष के लिए एक पंक्ति और फिर एक सारांश प्रिंट करता है। `--format json` समान निष्कर्षों को एक JSON ऑब्जेक्ट के रूप में देता है:

```
$ sil-lift validate dictionary.lift
चेतावनी [uri-not-rfc] dictionary.lift:6: <range href='file://C:/...'>: URI प्राधिकरण के रूप में Windows ड्राइव अक्षर का उपयोग (FLEx-शैली file://C:/)
त्रुटि [dangling-ref] dictionary.lift:88 (entry poʻo_a1b2): ref 'nope' किसी भी एंट्री आईडी/GUID या सेंस आईडी से मेल नहीं खाता
1 त्रुटि(एँ), 1 चेतावनी(एँ)

$ sil-lift validate dictionary.lift --format json
{
  "problems": [
    {
      "level": "warning",
      "code": "uri-not-rfc",
      "message": "<range href='file://C:/...'>: Windows drive letter used as URI authority (FLEx-style file://C:/)",
      "file": "dictionary.lift",
      "entry_id": null,
      "guid": null,
      "line": 6
    },
    {
      "level": "error",
      "code": "dangling-ref",
      "message": "ref 'nope' matches no entry id/guid or sense id",
      "file": "dictionary.lift",
      "entry_id": "po\u02bbo_a1b2",
      "guid": null,
      "line": 88
    }
  ],
  "summary": {
    "errors": 1,
    "warnings": 1,
    "allowed": 0
  }
}
```

`validate` के विकल्प:

- `--format json` CI/ऑटोमेशन के उपयोग के लिए stdout पर एक ही JSON ऑब्जेक्ट लिखता है (और कुछ नहीं)। उपरोक्त उदाहरण में स्कीमा देखें।
- `--strict` चेतावनियों को त्रुटियों के रूप में मानता है, और कोई भी चेतावनी मिलने पर 1 पर बाहर निकल जाता है। इसे बिल्ड को केवल त्रुटियों पर नहीं बल्कि बिल्कुल भी चेतावनियाँ न होने पर ही चलाने के लिए उपयोग करें।
- `--no-check-media` फ़ाइलसिस्टम मीडिया-उपस्थिति जाँच को छोड़ देता है, जिससे `missing-media` और `media-href-mismatch` निष्कर्ष दब जाते हैं। यह तब उपयोगी होता है जब एक्सपोर्ट की ऑडियो और फोटो फ़ाइलें कहीं और रखी गई हों, या अभी तक `.lift` के पास कॉपी नहीं की गई हों।
- `--allow CODE[,CODE...]` (दोहराया जा सकता है) दिए गए कोडों के निष्कर्षों की रिपोर्ट करता है, लेकिन उन्हें पास/फेल निर्णय से बाहर रखता है।
  - यह त्रुटियों और चेतावनियों दोनों पर लागू होता है, इसलिए एक अनुमत चेतावनी भी `--strict` को ट्रिप नहीं करती।
  - सारांश पंक्ति प्रत्येक कोड के लिए अनुमत निष्कर्षों की गिनती करती है; JSON सारांश का `allowed` उनका कुल बताता है।
  - जो कोड कभी नहीं आता, उसे अनदेखा कर दिया जाता है, इसलिए यदि कोई जांच बंद कर दी जाए तो अनुमत सूची काम करती रहती है।
- `--require-ids` अतिरिक्त रूप से किसी भी ऐसी प्रविष्टि पर विफल होता है जिसमें `guid` न हो या किसी सेंस में `id` न हो (एक `missing-id` त्रुटि)। यह स्थिर आईडी द्वारा पुनः आयात करने वाले वर्कफ़्लो के लिए LIFT की तुलना में अधिक सख्त है।

पथ के रूप में `-` पास करने पर दस्तावेज़ stdin से पढ़ा जाता है। एक पाइप्ड दस्तावेज़ का कोई फ़ोल्डर नहीं होता, इसलिए इसका साथी `.lift-ranges` और मीडिया हल नहीं होते।

!!! note

    `validate` के एग्जिट कोड और `--format json` स्कीमा एक समर्थित ऑटोमेशन इंटरफ़ेस हैं: दोनों टेस्ट द्वारा कवर किए गए हैं और केवल SemVer के तहत ही बदलते हैं।

## आँकड़े

```
$ sil-lift आँकड़े sango.lift
प्रविष्टियाँ: 3507
संवेदनाएँ: 4541
...
```

`stats` भी `--format json` लेता है, और गिनतियों को एक ही JSON ऑब्जेक्ट के रूप में उत्पन्न करता है।

## क्रमबद्ध करें

`sort` केवल `.lift` फ़ाइल को ही फिर से लिखता है; साथी `.lift-ranges` फ़ाइलें जस की तस रहती हैं (उन्हें [`RangesFile` API](folder-media.md#ranges) के साथ अलग से क्रमबद्ध करें)।

## निर्यात

`export` प्रत्येक लीफ़ सेंस के लिए एक पंक्ति लिखता है। `--langs` चुनता है कि किन भाषाओं को `gloss_` और `definition_` कॉलम मिलेंगे; डिफ़ॉल्ट रूप से इन्हें दस्तावेज़ से पता लगाया जाता है।

```
$ sil-lift export dictionary.lift --langs en,id -o dictionary.csv
```

## ज़िप किए गए पैकेज

`validate`, `stats`, `check-media`, और `export` एक ज़िप किए हुए (`.zip`) LIFT पैकेज को भी स्वीकार करते हैं। इसके फ़ाइलें आर्काइव रूट में या एक शीर्ष-स्तरीय फ़ोल्डर के अंदर रखी जा सकती हैं। कोई भी कमांड जो कुछ भी निकालता है, वह एक अस्थायी निर्देशिका में चला जाता है और कमांड समाप्त होने पर हटा दिया जाता है।

- स्ट्रीमिंग कमांड `stats` और `export` केवल `.lift` को ही निकालते हैं, इसलिए ये मीडिया-भारी पैकेजों पर सस्ते पड़ते हैं।
- `validate` और `check-media` को पूरे फ़ोल्डर की आवश्यकता होती है और वे इसकी सारी सामग्री निकालते हैं।

## आउटपुट एन्कोडिंग

सभी आउटपुट हर प्लेटफ़ॉर्म पर UTF-8 में होता है, चाहे वह कंसोल हो, पाइप हो, या `>` रीडायरेक्ट हो। यह कभी भी लोकेल एन्कोडिंग (Windows पर cp1252, C/POSIX लोकेल के तहत ASCII) नहीं है, जो LIFT सामग्री का प्रतिनिधित्व नहीं कर सकती। `sil-lift export dictionary.lift > dictionary.csv` इसलिए बिल्कुल वही बाइट्स लिखता है जो `-o dictionary.csv` लिखता है, जिसमें CRLF पंक्ति समाप्ति चिह्न भी शामिल हैं।

## निकास कोड

- `0`: सफलता। चेतावनियाँ तब तक रन को विफल नहीं करतीं जब तक `--strict` न हो।
- `1`: निष्कर्ष। एक सत्यापन त्रुटि, अनुपस्थित या गलत लिखा गया मीडिया, या `--strict` के अंतर्गत एक चेतावनी, तब तक 1 पर बाहर निकलती है जब तक कि उसका कोड `--allow` को नहीं दिया गया हो।
- `2`: I/O विफलता। इनपुट पढ़ा नहीं जा सका, या आउटपुट लिखा नहीं जा सका, उदाहरण के लिए क्योंकि डिस्क भर गई है या `head` जैसे रीडर ने पाइप बंद कर दिया है।
