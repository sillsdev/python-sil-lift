# Проверить

Проверка всегда выполняется явно — при загрузке и сохранении проверка никогда не выполняется неявно.

```python
import sil_lift

# Исчерпывающий подход: ленивый поток объектов Problems (схема + семантические слои).
for problem in sil_lift.iter_problems("dictionary.lift"):
    print(problem)
    # ошибка [dangling-ref] dictionary.lift:88 (запись apu): ссылка 'nope' совпадает с ...

# Быстрая остановка при ошибке: генерирует LiftValidationError при первой проблеме уровня ошибки.
sil_lift.validate_file("dictionary.lift")

# Состояние в памяти (сначала сериализуется — задокументированная нагрузка при работе с большими лексиконами):
lex = sil_lift.load("dictionary.lift")
problems = list(lex.iter_problems())
```

Каждая `Problem` содержит `level` (`"error"`/`"warning"`), фиксированный `code`, `message`, а также часть адреса, если таковая имеется: `file` (`None`, если в лексиконе нет пути), `entry_id`, если она относится к одной записи, `guid`, если объект, к которому она относится, имеет такой идентификатор (запись или элемент диапазона), и `line`, если она сопоставляется со строкой в документе. Вывод, касающийся диапазона, адресован сопутствующему объекту `.lift-ranges`, который его определяет, и не содержит записи. Незаполненные поля имеют значение `None` — `null` при использовании параметра `--format json`, где каждый ключ всегда присутствует.

## Слои

1. **RELAX NG** в соответствии с грамматикой LIFT 0.13 (включенной из пакета lift-standard — это байт-идентичная копия, добавленная в данный пакет).
2. **Схема диапазонов** — в данном проекте это файл `lift-ranges-0.13.rng` — охватывает каждый отслеживаемый компаньон `.lift-ranges`; она адресована именно компаньону, а не `.lift`.
3. **Семантические проверки**, которые невозможно выразить с помощью грамматики — девять таких проверок, по одному коду на каждую.

## Коды неисправностей

Каждый результат содержит один из этих элементов, в зависимости от того, на каком уровне он был сгенерирован — `schema` и `uri-not-rfc` относятся к уровням схем, а остальные девять представляют собой семантические проверки. Строки являются поддерживаемым интерфейсом; опция `--strict` преобразует каждое предупреждение в ошибку.

| код                                  | уровень        | что именно выявляет                                                                                               |
| ------------------------------------ | -------------- | ----------------------------------------------------------------------------------------------------------------- |
| `dangling-ranges-href`               | предупреждение | заголовок `range/@href`, для которого не найден соответствующий файл                                              |
| `dangling-ref`                       | ошибка         | `relation/@ref` или `variant/@ref`, не соответствующие ни одной записи или значению                               |
| `duplicate-form-lang`                | предупреждение | две формы в одном мультитексте, объединенные общим языком                                                         |
| `duplicate-guid`                     | ошибка         | идентификатор, повторно используемый в записях или в диапазонах/элементах диапазона одного документа              |
| `missing-id`                         | ошибка         | подписка через `require_ids`: запись без GUID, смысл без ID                                       |
| `отсутствующие медиафайлы`           | предупреждение | указанный аудио- или графический файл отсутствует на диске                                                        |
| `несоответствие нормализации`        | предупреждение | имя, которое обращается к идентификатору, на который оно указывает, только через NFC                              |
| `range-parent`                       | ошибка         | `range-element/@parent` не имеет идентификатора соседнего элемента                                                |
| `схема`                              | ошибка         | нарушение грамматики RELAX NG в файле `.lift` или в сопутствующем модуле                                          |
| `значение с недопустимым диапазоном` | предупреждение | значение признака, определяемое по грамматической информации или диапазону, которое не указано в данном диапазоне |
| `uri-not-rfc`                        | предупреждение | атрибут href, не являющийся допустимым URI — `file://C:/...` в FLEx                                               |

## Реальные результаты работы FieldWorks (FLEx)

FieldWorks систематически генерирует контент, который отклоняется строгой системой проверки. Вот правила sil-lift, позволяющие обеспечить эффективную проверку подлинности лексиконов:

- Ссылки `file://C:/...` (недопустимые URI) фиксируются как **предупреждения** (`uri-not-rfc`), а не как ошибки схемы — валидатор C# никогда их не отклонял.
- Дети, чередующиеся в соответствии с правилами (например, в некотором смысле `field, note, field, note`), **не** помечаются, что позволяет обойти ложное срабатывание в libxml2.
- Расширения `trait`/`field` из FLEx внутри `range-element` **упоминаются** (ошибки схемы по отношению к схеме диапазонов): это настоящие отклонения от спецификации.
- Имена преобразуются на основе диапазонов и идентификаторов элементов диапазонов в соответствии с **нормализацией NFC** Unicode — ссылок `parent`, значений диапазонов, а также имени `trait` или идентификатора заголовка `range`, который служит ключом для диапазона. При экспорте формат FLEx нормализуется до NFC, однако в некоторых случаях запись обходила этот этап, в результате чего `id` элемента диапазона может быть в формате NFD, в то время как его метки, собственный `parent` и значения `.lift`, определяющие его имя, находятся в формате NFC.
  - При точном сравнении корректный экспорт выглядит некорректным — а диапазон, в котором `id` написано иначе, вообще не проверяется, поскольку имя черты, не относящееся ни к одному диапазону, принимается без предупреждения.
  - Имя, совпадение которого было обнаружено только после нормализации, фиксируется как **предупреждение** `normalization-mismatch` — один раз на каждый идентификатор, независимо от количества несоответствий в ссылках, — с указанием файла, в котором оно определено. Данные верны, но пользователь, сравнивающий исходные строки, не сможет распознать эти ссылки.
  - Идентификаторы никогда не перезаписываются: в файле сохраняется исходное написание.
