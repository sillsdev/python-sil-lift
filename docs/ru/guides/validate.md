# Проверить

Проверка всегда выполняется явно: при загрузке и сохранении данные никогда не проверяются неявно.

```python
import sil_lift

# Исчерпывающий подход: ленивый поток объектов Problem (схема + семантические слои).
for problem in sil_lift.iter_problems("dictionary.lift"):
    print(problem)
    # ошибка [dangling-ref] dictionary.lift:88 (запись apu): ссылка 'nope' совпадает с ...

# Быстрая остановка при ошибке: остановка при первой проблеме уровня «error».
if any(p.level == "error" for p in sil_lift.iter_problems("dictionary.lift")):
    raise SystemExit(1)

# Состояние в памяти (сначала сериализуется, что, как указано в документации, увеличивает время обработки при работе с большими словарями):
lex = sil_lift.load("dictionary.lift")
problems = list(lex.iter_problems())
```

Каждая `Problem` содержит `level` (`"error"`/`"warning"`), фиксированный `code` и `message`, а также часть адреса, соответствующую обнаруженному нарушению:

- `file`: `None`, если у лексикона нет пути.
- `entry_id`: указывается, если находка относится к одной записи.
- `guid`: устанавливается, если соответствующий объект (запись или элемент диапазона) имеет такой идентификатор.
- `line`: устанавливается, когда результат поиска соответствует строке в документе.

Вывод, касающийся диапазона, адресован сопутствующему объекту `.lift-ranges`, который его определяет, и не содержит записи. Незаполненные поля имеют значение `None` (`null` при использовании параметра `--format json`, где каждый ключ всегда присутствует).

## Слои

1. **Схема LIFT** (`lift-0.13.rng`, грамматика LIFT 0.13 в формате RELAX NG, включенная в состав пакета lift-standard с идентичным байтовым содержанием) над файлом `.lift`.
2. **Схема диапазонов** (`lift-ranges-0.13.rng`, также поставляемая из пакета `lift-standard`) охватывает каждый отслеживаемый компаньон `.lift-ranges`; она адресована именно компаньону, а не `.lift`.
3. **Семантические проверки**, которые не могут быть выражены с помощью схем: их тринадцать, по одному коду на каждую.

## Коды неисправностей

Каждый результат содержит один из этих элементов, в зависимости от того, на каком уровне он был сгенерирован: `schema` и `uri-not-rfc` относятся к уровням схем, остальные — к семантическим проверкам. По умолчанию проверяется каждый код, за исключением `missing-id`, который включается отдельно: для его активации передайте параметр `require_ids=True` (или `--require-ids`). Коды являются стабильными, поэтому скрипты могут выполнять сопоставление по ним. Параметр `--strict` преобразует каждое предупреждение в ошибку. Команда `sil-lift validate --allow CODE` исключает данный код из оценки «прошел/не прошел».

| код                                  | уровень        | что именно выявляет                                                                                                  |
| ------------------------------------ | -------------- | -------------------------------------------------------------------------------------------------------------------- |
| `файл с неоднозначными диапазонами`  | предупреждение | несколько файлов, имеющих одно и то же имя-компаньон при преобразовании регистра и в формате NFC                     |
| `dangling-ranges-href`               | предупреждение | заголовок `range/@href`, для которого не найден соответствующий файл                                                 |
| `dangling-ref`                       | ошибка         | `relation/@ref` или `variant/@ref`, не соответствующие ни одной записи или значению                                  |
| `duplicate-form-lang`                | предупреждение | две формы в одном мультитексте, объединенные общим языком                                                            |
| `duplicate-guid`                     | ошибка         | идентификатор, повторно используемый в записях или в диапазонах/элементах диапазона одного документа                 |
| `form-missing-lang`                  | ошибка         | `<form>` или `<gloss>` без атрибута `lang`, который требуется по схеме                                               |
| `media-href-mismatch`                | предупреждение | a с атрибутом href, который обращается к файлу только при преобразовании регистра символов или при использовании NFC |
| `missing-id`                         | ошибка         | **[opt-in]** запись без GUID, значение без ID                    |
| `отсутствующие медиафайлы`           | предупреждение | указанный аудио- или графический файл отсутствует на диске                                                           |
| `несоответствие нормализации`        | предупреждение | имя, которое обращается к идентификатору, на который оно указывает, только через NFC                                 |
| `range-parent`                       | ошибка         | `range-element/@parent` не имеет идентификатора соседнего элемента                                                   |
| `схема`                              | ошибка         | нарушение грамматики RELAX NG в файле `.lift` или в сопутствующем модуле                                             |
| `значение с недопустимым диапазоном` | предупреждение | значение признака, определяемое по грамматической информации или диапазону, которое не указано в данном диапазоне    |
| `файл с нечитаемыми диапазонами`     | предупреждение | сопутствующий кандидат, который существует, но не является документом с читаемыми диапазонами                        |
| `uri-not-rfc`                        | предупреждение | атрибут href, не являющийся допустимым URI (например, `file://C:/...` в FLEx)                     |

### Что видит система проверки

Все три уровня работают с документом в том виде, в котором он сериализован, поэтому в случае документа, который вообще не поддается сериализации, выдается одна ошибка `lone-surrogate`. См. [Гарантии Fidelity](../fidelity.md#content-xml-cannot-represent).

Проверка является операцией только для чтения: она отображает документ в том виде, в каком он находится на данный момент, до того как при сохранении будет установлена метка `dateModified`. Маркеры никогда не вызывают ошибку, поэтому документ, прошедший проверку, после сохранения по-прежнему считается прошедшим проверку.

### Коды сопутствующих папок

Если имя-компаньон совпадает с несколькими файлами, ни один из них не загружается: определяемые ими диапазоны становятся недоступными до тех пор, пока все файлы, кроме одного, не будут переименованы или удалены.

Три кода, связанные с сопутствующими папками (`ambiguous-ranges-file`, `dangling-ranges-href` и `unreadable-ranges-file`), фиксируются только в том случае, если выполнялся процесс обнаружения сопутствующих папок:

- При загрузке с параметром `resolve_ranges=False` сопутствующие объекты выходят за пределы области видимости, поэтому ни один из них не отображается в отчете.
- Добавление одного из них позже с помощью `add_ranges_file()` не восстанавливает их, поскольку эта функция никогда не считывает содержимое папки, о которой сообщают эти коды.

Параметр `resolve_ranges=False` не влияет на `missing-media` или `media-href-mismatch`: медиафайлы никогда не преобразуются в модель, поэтому от чего-либо отказываться не приходится.

### Коды медиафайлов

sil-lift ищет каждый медиафайл по указанному атрибуту href, а также в папках `audio/` (файлы с произношением) или `pictures/` (иллюстрации). Эта папка — собственное предположение sil-lift, а не информация из документа, поэтому она может иметь любой вариант написания с учетом регистра, и её написание никогда не указывается.

Ошибки `missing-media` и `media-href-mismatch` делят между собой проверку медиафайлов: первая означает, что ни один файл не соответствует параметру href ни при каком варианте написания, вторая — что один файл соответствует, но параметр href не указывает его точное название. Второй вывод касается переносимости: файл находится здесь, и хост, обслуживающий эту папку и учитывающий регистр, не сможет его найти.

Папка с орфографической ошибкой в названии переименовывается независимо от того, сколько ссылок на неё имеется, поэтому она фиксируется в отчёте только один раз и не имеет записи. О каждой ошибке в написании _имени файла_ в отчете указывается ссылка на запись, в которой она была допущена.

## Реальные результаты работы FieldWorks (FLEx)

FieldWorks систематически генерирует контент, который отклоняется строгой системой проверки. Вот правила sil-lift, позволяющие обеспечить эффективную проверку подлинности лексиконов:

- Ссылки `file://C:/...` (недопустимые URI) регистрируются как **предупреждения** (`uri-not-rfc`), а не как ошибки схемы; валидатор C# никогда их не отклонял.
- Дети, чередующиеся в соответствии с правилами (например, в некотором смысле `field, note, field, note`), **не** помечаются; это позволяет избежать ложного срабатывания в libxml2.
- Расширения `trait`/`field` из FLEx внутри `range-element` **упоминаются** (ошибки схемы по отношению к схеме диапазонов): это настоящие отклонения от спецификации.
- Имена разрешаются на основе диапазонов и идентификаторов элементов диапазона в соответствии с **нормализацией NFC** Unicode: ссылки `parent`, значения диапазонов, а также имя `trait` или идентификатор заголовка `range`, служащий ключом для диапазона.
  - При экспорте формат FLEx нормализуется до NFC, однако в некоторых случаях запись обходила этот этап, в результате чего `id` элемента диапазона может быть в формате NFD, в то время как его метки, собственный `parent` и значения `.lift`, определяющие его имя, находятся в формате NFC.
  - При точном сравнении в этом случае возникнут две ошибки. Ссылки на идентификатор NFD будут отображаться как неработающие, хотя сам экспорт является корректным. А диапазон, собственное значение `id` которого является NFD, останется непроверенным: ни одно имя черты не будет с ним совпадать, а черта, имя которой не совпадает ни с одним диапазоном, принимается без изменений.
  - Имя, совпадение которого было обнаружено только после нормализации, фиксируется как **предупреждение** `normalization-mismatch` — один раз на каждый идентификатор, а не на каждую ссылку, — и направляется в файл, в котором оно определено. Данные верны, но пользователь, сравнивающий исходные строки, не сможет распознать эти ссылки.
  - Идентификаторы никогда не перезаписываются: в файле сохраняется исходное написание.
