# Папка LIFT: диапазоны и носители

Лексикон LIFT обычно представляет собой _папку_: файл `.lift`, один или несколько сопутствующих файлов `.lift-ranges` (файлы-«сайдкар») и мультимедийные файлы в папках `audio/` и `pictures/`.

## Диапазоны

```python
lex = sil_lift.load("dictionary.lift")      # сопутствующие файлы отслеживаются автоматически

lex.ranges_files                            # {Path(...): RangesFile}
lex.all_ranges()                            # объединенное представление {id: Range}
lex.all_ranges()["grammatical-info"].elements
```

Функция `lex.save()` записывает файл `.lift` и все отслеживаемые сопутствующие файлы одновременно. Изменения, внесенные в файл `RangesFile`, сохраняются обратно в _этот_ файл; неизмененные диапазоны сохраняют свои точные байты. Использование в автономном режиме:

```python
ranges = sil_lift.RangesFile.load("dictionary.lift-ranges")
ranges.find("grammatical-info")
ranges.sort()
ranges.save()
```

### Поиск спутников

Проверяется несколько кандидатов, и загружается каждый отдельный файл из их числа.

- Заголовок `range/@href`, указывающий на существующий файл, используется в том виде, в каком он задан.
- Если ссылка `href` не приводит никуда, в качестве запасного варианта используется её базовое имя с добавлением расширения `.lift`. FieldWorks записывает неполные абсолютные пути `file://C:/...` с компьютера-экспортера, и именно этот резервный вариант обеспечивает их работу в локальной среде.
- Обычный элементы одного уровня `<name>.lift-ranges` учитывается даже в том случае, если на него нет никаких ссылок.

Имена, различающиеся лишь регистром или нормализацией Unicode, по-прежнему сопоставляются (`Dict.LIFT` находит `Dict.lift-ranges`), за исключением случаев, когда одно имя соответствует нескольким файлам: в таком случае ни один из них не загружается, и об этом сообщается как [`ambiguous-ranges-file`](validate.md#problem-codes).

Кандидат, который не может быть прочитан как документ формата `<lift-ranges>` (например, файл размером в ноль байт, полученный в результате прерванного экспорта), пропускается, а не приводит к сбою загрузки, и указывается в отчёте как [`unreadable-ranges-file`](validate.md#problem-codes). При прямой загрузке с помощью `RangesFile.load()` вместо этого возникает исключение.

Передайте параметр `resolve_ranges=False` в функцию `load()`, чтобы пропустить поиск сопутствующих объектов.

## СМИ

```python
for ref in lex.media_refs():        # все ссылки типа <media> и <illustration>
    print(ref.kind, ref.href, ref.entry_id)

lex.check_media()                   # ссылки, которые не разрешаются корректно
```

Разрешение осуществляется в соответствии со стандартной схемой: относительный атрибут href проверяется в том виде, в котором он указан, и находится в каталоге `audio/` (для аудиофайлов с произношением) или `pictures/` (для иллюстраций). Обратные косые черты обрабатываются как прямые косые черты, поскольку WeSay формирует ссылки в формате `pictures\photo with space.png`. Удаленные и абсолютные ссылки не проверяются и пропускаются.

Функция `check_media()` выводит только те ссылки, которые не были успешно разрешены, по одному объекту `MediaResolution` для каждой:

- `status="missing"`: ни один файл не соответствовал указанному в атрибуте href, независимо от вариантов написания.
- `status="mismatch"`: одно из них совпало, но только при преобразовании регистра или в режиме NFC; `found` указывает на файл на диске.

Сообщается о несоответствии, хотя файл был найден. Имя сопутствующего файла сопоставляется приблизительно без каких-либо комментариев, однако ссылка href на медиафайл также считывается тем сервером, который впоследствии обслуживает эту папку, и хост, учитывающий регистр, не сможет найти этот файл. В отчете о валидации описан тот же случай, что и в [`media-href-mismatch`](validate.md#problem-codes).

## Другое содержимое папки

В папке LIFT часто хранятся файлы, которые sil-lift не моделирует, например, LDML для систем письма в каталоге `WritingSystems/` или файлы с согласием говорящих для проекта «The Combine» в каталоге `consent/`. Функции `load()` и `save()` оставляют их без изменений, а [`Lexicon.save_zip()`](lift-export-interop.md) при упаковке папки копирует их дословно.
