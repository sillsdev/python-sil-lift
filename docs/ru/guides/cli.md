# Командная строка (CLI)

При установке пакета (`pip install sil-lift`) также устанавливается команда `sil-lift`.

```
sil-lift validate PATH [--format {text,json}] [--strict] [--no-check-media]
                  [--allow CODE[,CODE...]]... [--require-ids]
    все проблемы с указанием файла/записи/строки; выход с кодом 1 при ошибках

sil-lift stats PATH [--format {text,json}]
    подсчёт записей/значений/языков (потоково; любой размер)

sil-lift sort PATH [-o OUT]
    канонически отсортированная копия, готовая к сравнениям (по умолчанию: на месте)

sil-lift check-media PATH
    отчёт об отсутствующих, неправильно написанных и осиротевших медиафайлах; выход с кодом 1 при отсутствии/ошибке в написании

sil-lift export PATH [-o OUT] [--langs L] [--tsv]
    по одной строке на каждый листьевой сенс (подсенсы сглажены) в формат CSV/TSV (потоковая передача)
```

## проверить

Команда `validate` выводит по одной строке на каждое обнаруженное нарушение, а затем — сводку. `--format json` выдает те же результаты в виде одного объекта JSON:

```
$ sil-lift validate dictionary.lift
предупреждение [uri-not-rfc] dictionary.lift:6: <range href='file://C:/...'>: Буква диска Windows используется в качестве авторитета URI (file://C:/ в стиле FLEx)
ошибка [dangling-ref] dictionary.lift:88 (запись poʻo_a1b2): ссылка «nope» не соответствует ни одному идентификатору записи (ID/GUID), ни идентификатору значения
1 ошибка, 1 предупреждение

$ sil-lift validate dictionary.lift --format json
{
  "problems": [
    {
      "level": "warning",
      "code": "uri-not-rfc",
      "message": "<range href='file://C:/...'>: В качестве авторитета URI использована буква диска Windows (file://C:/ в стиле FLEx)",
      "file": "dictionary.lift",
      "entry_id": null,
      "guid": null,
      "line": 6
    },
    {
      "level": "error",
      "code": "dangling-ref",
      "message": "ссылка 'nope' не соответствует ни одному id/guid записи или sense id",
      "file": "dictionary.lift",
      "entry_id": "po\u02bbo_a1b2",
      "guid": null,
      "line": 88
    }
  ],
  "summary": {
    "errors": 1,
    "warnings": 1,
    "allowed": 0
  }
}
```

Параметры функции `validate`:

- `--format json` выводит в stdout один объект JSON (и ничего больше) для использования в системах непрерывной интеграции и автоматизации. См. схему в приведенном выше примере.
- `--strict` рассматривает предупреждения как ошибки и возвращает значение 1 при обнаружении хотя бы одного из них. Используйте эту функцию, чтобы запускать сборку при полном отсутствии предупреждений, а не только при наличии ошибок.
- `--no-check-media` пропускает проверку наличия медиафайлов в файловой системе, подавляя обнаружение ошибок `missing-media` и `media-href-mismatch`. Это пригодится, если аудиофайлы и фотографии, экспортированные из проекта, хранятся в другом месте или ещё не скопированы в папку рядом с файлом `.lift`.
- `--allow CODE[,CODE...]` (повторяемо) выводит результаты проверки по указанным кодам, но не учитывает их при принятии решения о прохождении или не прохождении теста.
  - Это относится как к ошибкам, так и к предупреждениям, поэтому допустимое предупреждение также не приводит к срабатыванию параметра `--strict`.
  - В строке сводки подсчитываются допустимые результаты по каждому коду; в сводке JSON в поле `allowed` указано их общее количество.
  - Код, который никогда не встречается, игнорируется, поэтому список разрешенных элементов продолжает действовать даже в случае исключения какой-либо проверки.
- `--require-ids` также выдает ошибку (`missing-id`) при наличии любой записи, в которой отсутствует `guid`, или значения, в котором отсутствует `id`. Это более строгие требования, чем в LIFT, для рабочих процессов, в которых происходит повторный импорт по стабильному идентификатору.

Если в качестве пути указано `-`, документ считывается из стандартного входа. У документа, передаваемого по каналу, нет папки, поэтому сопутствующий файл `.lift-ranges` и мультимедийные файлы не определяются.

!!! note

    Коды завершения функции `validate` и схема `--format json` представляют собой поддерживаемый интерфейс автоматизации: оба элемента проходят тестирование и изменяются только в соответствии с SemVer.

## статистика

```
$ sil-lift stats sango.lift
записей:   3507
измерений:    4541
...
```

Команда `stats` также поддерживает опцию `--format json`, выводя результаты подсчёта в виде одного объекта JSON.

## сортировать

`sort` перезаписывает только файл `.lift`; сопутствующие файлы `.lift-ranges` остаются без изменений (их следует сортировать отдельно с помощью [API `RangesFile`](folder-media.md#ranges)).

## экспорт

Команда `export` записывает по одной строке на каждую ячейку листья. `--langs` определяет, для каких языков будут созданы столбцы `gloss_` и `definition_`; по умолчанию они определяются на основе документа.

```
$ sil-lift export dictionary.lift --langs en,id -o dictionary.csv
```

## Пакеты с застежкой-молнией

Функции `validate`, `stats`, `check-media` и `export` также принимают LIFT-пакет в формате ZIP (`.zip`). Его файлы могут находиться в корневом каталоге архива или внутри одной папки верхнего уровня. Все, что извлекает команда, помещается во временный каталог и удаляется по завершении работы команды.

- Команды потоковой обработки `stats` и `export` извлекают только сам файл `.lift`, поэтому их выполнение не требует значительных ресурсов даже при работе с пакетами, содержащими большие объемы данных.
- Для команд `validate` и `check-media` требуется вся папка, и необходимо распаковать её полностью.

## Кодирование выходных данных

Весь вывод формируется в кодировке UTF-8 на любой платформе, независимо от того, направляется ли он в консоль, в канал или через перенаправление `>`. Дело никогда не заключается в кодировке локали (cp1252 в Windows, ASCII в локали C/POSIX), которая не может отобразить контент LIFT. Таким образом, команда `sil-lift export dictionary.lift > dictionary.csv` записывает ровно те же байты, что и команда `-o dictionary.csv`, включая символы CRLF в конце строк.

## Коды завершения

- `0`: успех. Предупреждения не приводят к сбою выполнения, если не указан параметр `--strict`.
- `1`: выводы. Ошибка валидации, отсутствие носителя или ошибка в его названии, а также предупреждение при использовании опции `--strict` приводят к завершению с кодом 1, если только соответствующий код не был указан в опции `--allow`.
- `2`: Сбой ввода-вывода. Не удалось прочитать входные данные или записать выходные данные, например, из-за того, что диск заполнен или программа чтения, такая как `head`, закрыла канал.
