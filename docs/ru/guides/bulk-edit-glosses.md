# Пример с решением: массовое редактирование глосс

Типичная задача по обслуживанию: привести правописание всех английских терминов в словаре к единому стандарту (британский → американский или наоборот), не затрагивая при этом остальные элементы файла. В данном примере подробно рассматривается один скрипт, который выполняет загрузку, редактирование, проверку и сохранение данных, демонстрируя совместную работу API редактирования и гарантии точности.

## Сценарий

```python
import sys

import sil_lift

path = "dictionary.lift"
lex = sil_lift.load(path)

edited_glosses = 0

for entry in lex.entries:
    for sense in entry.all_senses():
        for gloss in sense.glosses:
            if gloss.lang != "en":
                continue
            old = str(gloss.text)
            new = old.replace("colour", "color")
            if new != old:
                gloss.text = sil_lift.Text([new])
                edited_glosses += 1

changed = lex.changed_entries()

errors = [p for p in lex.iter_problems() if p.level == "error"]
if errors:
    for problem in errors:
        print(problem)
    sys.exit(f"прерывание: {len(errors)} ошибок валидации, ничего не сохранено")

lex.save()
print(f"отредактированы {edited_glosses} глоссы в {len(changed)} записях")
```

Несколько моментов, на которые стоит обратить внимание:

- `entry.all_senses()` возвращает все значения _и подзначения_, в порядке глубинного обхода по порядку их появления в документе.
  - `entry.senses` содержит только элементы верхнего уровня, поэтому при массовом редактировании, проходящем по этому списку, любые глоссы, вложенные под подзначениями, будут незаметно пропущены.
- `gloss.text` — это объект типа `Text`, а не обычная строка: функция `str(gloss.text)` преобразует его в строку для сопоставления, а результат замены записывается обратно с помощью `sil_lift.Text([new])`, а не путем изменения исходной строки на месте.
- `lex.changed_entries()` возвращает записи, содержание которых отличается от содержимого загруженного файла. При внесении изменений в любом месте записи, даже во вложенном подзначении, эта запись помечается как отредактированная. Присвоение полю значения, которое у него уже было, не вызывает никаких сообщений, поскольку содержимое остаётся неизменным.
- Функция `changed_entries()` учитывает только содержимое записей, поэтому она служит для подсчёта, а не для защиты от записи. Чтобы пропустить сохранение, которое ничего не изменит, используйте `lex.changes()`; см. раздел [Сохранение](read-edit-write.md#saving).
- При проверке в памяти (`lex.iter_problems()`) сначала выполняется сериализация отредактированного состояния, благодаря чему оно правильно отражает внесенные изменения ещё до записи на диск. Прерывание при возникновении любой `Problem` уровня `"error"` (решение по поводу предупреждений остается за вызывающей стороной) означает, что некорректное изменение никогда не доходит до вызова `save()`.
- Функция `lex.save()` устанавливает новое значение `dateModified` именно для тех записей, которые были изменены этим скриптом, а также заполняет поле `dateCreated`, если оно было пустым.
  - И FieldWorks, и функция импорта LIFT от The Combine определяют, какие данные обновлять, на основе параметра `dateModified`, поэтому без указания новой даты они будут рассматривать отредактированные записи как неизменённые.
  - Маркировка наносится только на элементы `<entry>`. При редактировании пояснения к подзначению дата указывается в соответствующей статье, а не в самом значении.

## Выгода от точности воспроизведения

Гарантия распространяется на каждую отдельную запись: запись, модель которой не изменилась, возвращается в виде **байтово идентичного** копирования исходного значения, а повторная сериализация производится только для тех записей, которые вы действительно изменили. В приведенном выше фрагменте в одной записи были отредактированы глоссы; все остальные записи в файле сохранили свои байты без изменений. Таким образом, при редактировании одного глоссария в словаре, содержащем 50 000 статей, создается файл diff, затрагивающий одну статью, а не переформатированный файл.

Обратите внимание на степень детализации: при редактировании любой части записи происходит повторная сериализация всей записи целиком, включая нетронутые родственные значения. Точные условия договора см. в разделе [Гарантии Fidelity](../fidelity.md).

## За пределами глосс

Тот же подход применим и к другим многоязычным полям. Глоссы представляют собой список объектов `Form`, однако определения и большинство других многоязычных полей являются сопоставлениями `Multitext`, ключом которых является язык, поэтому редактирование сводится к простому присваиванию:

```python
sense.definition["en"] = "цвет предмета"
```

О том, как работает это сопоставление, см. [Многоязычный текст](read-edit-write.md#multilingual-text).
