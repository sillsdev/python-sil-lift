# Крупные файлы (потоковая передача)

Функция `load()` создаёт весь граф объектов. В случае лексиконов объёмом в несколько сотен МБ потоковый API обрабатывает по одной записи за раз в пределах ограниченного объёма памяти. Он возвращает тот же тип `Entry`, поэтому код, написанный для одного режима, работает и в другом.

## Чтение

```python
import sil_lift

with sil_lift.open_reader("big.lift") as reader:
    header = reader.header            # проанализировано заранее (расположено перед записями)
    for entry in reader:              # ленивый итератор Iterator[Entry]
        ...
```

## Письмо

```python
with sil_lift.open_reader("big.lift") as reader, sil_lift.open_writer(
    "out.lift", header=reader.header, producer="my-script"
) as writer:
    for entry in reader:
        if not entry.date_deleted:    # например, пропустить записи, помеченные как удалённые
            writer.write(entry)
```

Примечания:

- Результат работы этого модуля точно соответствует тому, что выдал бы канонический сериализатор полного документа для того же самого контента; эти два режима никогда не расходятся.
- В режиме потоковой передачи байты исходных данных не используются повторно: выходные данные всегда являются каноническими. Остатки LIFT на корневом уровне (комментарии между записями и атрибуты, не входящие в схему, в файле `<lift>`) удаляются, но записи и заголовок сохраняют свои собственные остатки.
- В отличие от [`Lexicon.save()`](../fidelity.md#saving-an-edited-document), в потоковом режиме временные метки не генерируются. Запись формируется с учетом уже имеющихся дат: потоковый пропуск никогда не видит документ в его первоначальном виде, поэтому он не может определить, какие записи вы изменили. Вручную установите значение `entry.date_modified` для тех записей, которые перезаписываются в ходе этого прохода.
- Если в блоке `open_writer` происходит исключение, файл остаётся явно незавершённым (без закрывающего вызова `</lift>`). Это позволяет избежать ситуации, когда наполовину составленный словарь выглядит законченным.
