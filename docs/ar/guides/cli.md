# سطر الأوامر (CLI)

يؤدي تثبيت الحزمة (`pip install sil-lift`) إلى تثبيت الأمر `sil-lift` أيضًا.

```
sil-lift validate PATH [--format {text,json}] [--strict] [--no-check-media]
                  [--allow CODE[,CODE...]]... [--require-ids]
    جميع المشكلات، مع الإشارة إلى الملف/المدخل/السطر؛ الخروج برمز 1 في حالة وجود أخطاء

sil-lift stats PATH [--format {text,json}]
    أعداد المدخلات/المعاني/اللغات (بشكل متدفق؛ بأي حجم)

sil-lift sort PATH [-o OUT]
    نسخة مرتبة بشكل قياسي وجاهزة للمقارنة (الافتراضي: في المكان نفسه)

sil-lift check-media PATH
    تقرير عن الوسائط المفقودة أو التي بها أخطاء إملائية أو اليتيمة؛ الخروج 1 في حالة وجود وسائط مفقودة أو بها أخطاء إملائية

sil-lift export PATH [-o OUT] [--langs L] [--tsv]
    صف واحد لكل معنى فرعي (مع المعاني الفرعية المسطحة) إلى CSV/TSV (بشكل متواصل)
```

## التحقق من صحة

تقوم وظيفة `validate` بطباعة سطر واحد لكل نتيجة، ثم ملخصًا. يُظهر `--format json` النتائج نفسها في شكل كائن JSON واحد:

```
$ sil-lift validate dictionary.lift
تحذير [uri-not-rfc] dictionary.lift:6: <range href='file://C:/...'>: استخدام حرف محرك أقراص Windows كمرجع URI (بأسلوب FLEx file://C:/)
خطأ [dangling-ref] dictionary.lift:88 (المدخل poʻo_a1b2): المرجع 'nope' لا يتطابق مع أي معرف إدخال/معرف فريد (GUID) أو معرف معنى
خطأ واحد، تحذير واحد

$ sil-lift validate dictionary.lift --format json
{
  "problems": [
    {
      "level": "warning",
      "code": "uri-not-rfc",
      "message": "<range href='file://C:/...'>: استخدام حرف محرك أقراص Windows كسلطة URI (بأسلوب FLEx file://C:/)",
      "file": "dictionary.lift",
```

خيارات `validate`:

- يُخرج الأمر `--format json` كائن JSON واحد إلى stdout (ولا شيء غير ذلك) لاستخدامه في عمليات التكامل المستمر (CI) والأتمتة. انظر المخطط الوارد في المثال أعلاه.
- تتعامل الخيار `--strict` مع التحذيرات على أنها أخطاء، وتُخرج القيمة 1 في حالة العثور على أي منها. استخدمها لتقييد عملية البناء بحيث لا يتم السماح بها إلا في حالة عدم وجود أي تحذيرات على الإطلاق، بدلاً من السماح بها في حالة وجود الأخطاء فقط.
- تتخطى الخيار `--no-check-media` عملية فحص وجود الوسائط في نظام الملفات، مما يؤدي إلى إخفاء النتائج المتعلقة بـ `missing-media` و`media-href-mismatch`. يكون هذا مفيدًا عندما تكون ملفات الصوت والصور الخاصة بالتصدير مخزنة في مكان آخر، أو لم يتم نسخها بجانب ملف `.lift` بعد.
- `--allow CODE[,CODE...]` (قابل للتكرار) يعرض نتائج الرموز المحددة، لكنه يستبعدها من قرار النجاح أو الفشل.
  - وينطبق ذلك على الأخطاء والتحذيرات على حد سواء، لذا فإن التحذير المسموح به لا يؤدي إلى تفعيل الخيار `--strict` أيضًا.
  - يُجمِّع سطر الملخص النتائج المسموح بها لكل رمز؛ بينما تُقدِّم الخاصية `allowed` في ملخص JSON إجمالي هذه النتائج.
  - يتم تجاهل الرمز الذي لا يظهر أبدًا، لذا تظل قائمة السماح تعمل حتى في حالة سحب أحد العناصر من القائمة.
- كما أن `--require-ids` تفشل (تظهر رسالة خطأ `missing-id`) في حالة أي إدخال يفتقر إلى `guid` أو أي معنى يفتقر إلى `id`. وهذا أكثر صرامة من LIFT، بالنسبة لسير العمل الذي يعيد الاستيراد باستخدام معرّف ثابت.

عند تمرير `-` كمسار، يتم قراءة المستند من المدخل القياسي (stdin). لا يحتوي المستند المُمرَّر عبر الأنابيب على مجلد، لذا لا يتم تحديد موقع الملف المصاحب له `.lift-ranges` والوسائط.

!!! note

    تُعد رموز الخروج الخاصة بـ `validate` ومخطط `--format json` واجهة أتمتة مدعومة: حيث يخضع كلاهما للاختبارات ولا يتغيران إلا وفقًا لمعايير SemVer.

## الإحصائيات

```
$ sil-lift stats sango.lift
عدد الإدخالات:   3507
عدد الاستشعارات:    4541
...
```

كما تقبل `stats` الخيار `--format json`، حيث تُخرج الأعداد في شكل كائن JSON واحد.

## فرز

تقوم وظيفة `sort` بإعادة كتابة ملف `.lift` فقط؛ أما الملفات المصاحبة `.lift-ranges` فتبقى دون تغيير (يمكن فرزها بشكل منفصل باستخدام [واجهة برمجة التطبيقات [`RangesFile`]](folder-media.md#ranges)).

## تصدير

تقوم `export` بكتابة صف واحد لكل وحدة تخزين أوراق. يحدد `--langs` اللغات التي تُضاف إليها أعمدة `gloss_` و`definition_`؛ ويتم تحديدها افتراضيًا من المستند.

```
$ sil-lift export dictionary.lift --langs en,id -o dictionary.csv
```

## الحزم المضغوطة

تقبل الأوامر `validate` و`stats` و`check-media` و`export` أيضًا حزمة LIFT مضغوطة (`.zip`). يمكن أن توجد ملفاته في جذر الأرشيف أو داخل مجلد واحد من المستوى الأعلى. يتم نقل كل ما يستخرجه الأمر إلى دليل مؤقت، ويتم التخلص منه عند انتهاء تنفيذ الأمر.

- تستخرج أوامر البث `stats` و`export` ملف `.lift` نفسه فقط، لذا فإنها لا تستهلك موارد كثيرة عند التعامل مع الحزم التي تحتوي على ملفات وسائط كثيرة.
- تحتاج وظيفتا `validate` و`check-media` إلى المجلد بأكمله، ويجب استخراج محتوياته بالكامل.

## ترميز المخرجات

يتم إخراج جميع البيانات بتنسيق UTF-8، على جميع الأنظمة الأساسية وسواء تم إرسالها إلى وحدة التحكم أو إلى أنبوب أو إلى إعادة توجيه `>`. ليس الترميز المحلي أبدًا (cp1252 في نظام ويندوز، أو ASCII في الإعدادات المحلية لـ C/POSIX) هو الذي لا يستطيع تمثيل محتوى LIFT. وبالتالي، فإن الأمر `sil-lift export dictionary.lift > dictionary.csv` يكتب بالضبط نفس البايتات التي يكتبها الأمر `-o dictionary.csv`، بما في ذلك علامات نهاية الصفوف CRLF.

## رموز الخروج

- `0`: نجاح. لا تؤدي التحذيرات إلى فشل عملية التشغيل ما لم يتم استخدام الخيار `--strict`.
- `1`: النتائج. يؤدي حدوث خطأ في التحقق من الصحة، أو وجود ملفات وسائط مفقودة أو بها أخطاء إملائية، أو ظهور تحذير عند استخدام الخيار `--strict` إلى إنهاء العملية برمز 1، ما لم يتم إدراج رمزها في الخيار `--allow`.
- `2`: فشل في الإدخال/الإخراج. تعذر قراءة المدخلات، أو تعذر كتابة المخرجات، على سبيل المثال بسبب امتلاء القرص أو لأن أداة قراءة مثل `head` أغلقت الأنبوب.
